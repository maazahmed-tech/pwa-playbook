# 12 — UI: the branded prototype (standalone HTML)

**Where this sits:** after [11-wireframes.md](11-wireframes.md). The output of this milestone is the visual and behavioural spec that [13-fullstack-frontend.md](13-fullstack-frontend.md) ports 1:1 into a real Next.js app. The tech-stack decision round happens at the very end of this milestone and is documented in [04-tech-stack.md](04-tech-stack.md).

## Goal

Take the greyscale prototype and make it look and feel like the finished product, still as **one self-contained HTML file** deployed on Vercel:

- the full **design system** applied (dark-first tokens, glass surfaces, gradient CTAs, type scale, motion) — written as CSS variables so the real app can copy it verbatim;
- **real imagery**: an AI-generated photo library, a custom icon set and (if relevant) compressed 3D models, all produced from prompt briefs Claude writes and you generate;
- **data truth**: every card opens its own data, counts are derived, money state is real (credits, gates, upsell);
- the **signature brand moments** (animated logo at splash and while the AI "thinks");
- the client-facing docs (coverage, walkthrough, presenter script, in-app flow charts) kept in step every round;
- a written **UI-Build-Playbook.md** at the end so the next app can skip straight to branded.

If you skipped the greyscale stage, this milestone is where you build the prototype from scratch **with styled placeholders** — the same architecture as [11-wireframes.md](11-wireframes.md) Step 2, styled from day one.

## Prerequisites checklist

- [ ] The prototype repo from milestone 11 (or an empty repo) and its Vercel project. Repo-local git identity set to the owner's noreply address (Vercel blocks other authors on private repos).
- [ ] `BRAND.md` and the brand files (logo concept PDF, the coming-soon `index.html` — it already contains the live CSS logo animation and the ambient background recipe).
- [ ] Any 3D models (`.glb`) you want in the prototype, uncompressed, in a folder outside the repo.
- [ ] An image-generation tool you can drive by hand (Assemble used Gemini's app). Claude writes the prompts; you generate and save the files.
- [ ] Skills available in the session: `frontend-design`, `gsap-scrolltrigger`, `threejs-webgl` (or the equivalents). Ask Claude whether anything else is worth installing; the answer in Assemble was "no, the installed set covers it".
- [ ] Python via `py` + Pillow (slicing), Node 22 (a small local dev server), `npx @gltf-transform/cli` reachable (GLB compression).
- [ ] Two to three evenings. Assemble's UI phase ran 5–6 Aug 2026 in eight rounds (about 28 hours of session time including a context compaction), plus a short playbook and tech-stack session on 19–21 Aug.

## Step 2 — The big design decision round (one question at a time)

Plain English: thirty small decisions made together beat one big brief. Each question has 2–4 options with a one-line trade-off and one marked "(Recommended)". Your free-text answers can correct assumptions or add scope; Claude folds them into the next question.

The round should cover, in this order: theme (dark/light first) · personality in three words · accent discipline (where the accent colour is allowed) · architecture (restyle the same file in place vs rebuild) · scope order (customer first, then admin) · motion level · animation engine (GSAP via CDN worked; the real app later used Motion for React) · 3D approach · where the animated logo appears (splash + loading moments only) · imagery source (AI-generated set) · who makes the images ("you generate, Claude briefs") · shapes and radii · card style (glass vs layered) · background atmosphere · primary button · mobile nav (floating dock with a centre action) · the AI "thinking" moment · screen transitions · type scale · which font is for labels/data · modals (bottom sheets on mobile, centred dialogs on desktop) · launcher · onboarding style · PWA manifest now, service worker later · ads and upsell treatment · desktop layout (side rail, same components) · one delivery vs milestones · branch as the safety net · empty states and toasts · guardrails (reduced motion, AA contrast on glass, limited blur, 44 px targets).

> **For Claude — paste this:**
> ```
> We are converting the greyscale prototype into the branded product UI — same single file, restyled in place so every screen keeps working.
> Ask at least 30 questions to understand, discuss and take decisions together. Ask them ONE BY ONE, each as multiple choice, and mark the option you recommend (with a one-line reason). Include small previews of values where it helps (hex, px, timings). Cover at least: [paste the list above].
> After the last answer: summarise every decision; write "[App] - Image Brief.md" with one AI image prompt per placeholder (exact target filenames, one shared style paragraph, portrait 3:4 where the UI is portrait, no text/logos/watermarks); then wait for my "start the build".
> ```

> **Assemble example.** 5 Aug 2026, 03:31–04:10: 30 questions in 37 minutes. Chosen: dark navy `#0F111F` first; "premium editorial, not a shopping cart"; purple only on CTAs/active/focus, cyan rare; restyle in place; rich cinematic motion (over the recommended "polished micro-interactions"); GSAP from CDN; real Draco-compressed GLB; orbit logo only at splash and loading ("the brand moment IS the wait moment"); glassmorphism cards over ambient blobs + grain + vignette; gradient pill CTA `#A98EEF→#8F6EF2` with navy text; floating glass dock with a glowing centre Match button; branded 2–3 s AI generation sequence; 15 px base type with thin display headings; manifest and icons now, **no service worker** (cache invalidation makes a prototype painful to iterate); one full delivery on branch `redesign-v1`. Output: `Assemble - Image Brief.md` with 43 prompts.

## Step 4 — Asset rounds: Claude briefs, you generate, Claude slices and wires

Plain English: Claude cannot generate images in the session. It writes copy-paste prompts; you run them in your image tool and drop the files in a folder; Claude does the rest.

Rules that were learned the hard way (put them in the brief every time):

1. **Contact sheets with baked labels.** Ask for grids (at most 3×3 for fidelity; 4×4 for icons) where each tile has its **filename printed under it**. Generators shuffle positions and sometimes return a 5×3 instead of a 3×3 — Claude maps cells by reading the labels, never by prompt order, and skips duplicates.
2. **Read the real sheet size** before slicing (the same prompt returns different pixel sizes).
3. **Photos**: one shared style paragraph (backdrop colour ramp, key light + rim light in the accent colour, grain, "no text, logos or watermarks"), portrait 3:4, saved as JPEG ~900–1280 px at quality ~86. Normalise double extensions (`.jpg.png`).
4. **Icons**: white line-art on the brand background → luminance to alpha, crop to the glyph plus padding, square 96 px PNG → served as **CSS mask images tinted with `currentColor`** (muted when inactive, accent + glow when active). One icon language across the set; stroke consistency matters more than any single icon. If a ring motif carries the brand word, say the word appears **exactly once** per ring (the first grids repeated it like a pattern).
5. **Worn/hero images with a person**: use a **generic AI model**, not the client, to avoid likeness questions.
6. **3D**: Draco-compress every model; one viewer shared by all 3D screens; a per-URL promise cache.
7. Write helper scripts as `.py` files in the scratchpad and run them with `py` — never inline Python in PowerShell.
8. If the browser pane has to save something it rendered (e.g. four views of a GLB drawn in the page), run a tiny same-origin Node dev server with a `POST /save?name=` endpoint into `img/` (gitignored `.claude/dev-server.js`). Cross-origin fetches and downloads are blocked in the pane.

> **For Claude — paste this (grid prompts):**
> ```
> Write one copy-paste prompt per sheet for [GENERATOR] to make a [ROWS]x[COLS] grid of [ITEMS]. Shared style paragraph first (backdrop hex, lighting, stroke/scale consistency, no logos/watermarks, "the ring text appears EXACTLY ONCE" if rings are used). Then a numbered cell map with the filename printed under each cell in small white text. Leave the bottom-right tile(s) EMPTY. Append the prompts to "[App] - Icon Brief.md" / "- Image Brief.md".
> ```

> **For Claude — paste this (asset intake):**
> ```
> New generated assets are in [FOLDER]. For each sheet: read the real pixel size first; find cells by the baked labels (skip duplicates); crop each cell and trim the label strip; check nothing is clipped (compare the glyph/garment bounding box to the crop). Photos: JPEG ~1280px q86, 3:4 where the UI is portrait. Icons: luminance→alpha, crop to bounds + padding, square 96px PNG, check alpha coverage numerically. 3D: Draco-compress to under ~6MB. Save under the exact filenames from the brief; normalise double extensions. Verify every surface that uses them in the browser, zero console errors, then commit and push. Write helper scripts as .py files in the scratchpad.
> ```

> **Assemble example.** 5 Aug 17:39: four contact sheets sliced into 49 files; an **imagery engine** (`window.AIMG`: ordered text-matching rules that map placeholder boxes to files, a `data-iimg` override that always wins, and a probe "if `worn-*.jpg` exists, switch every look surface to worn images") lit 73 placeholders. 22:18: twelve "worn look" photos dropped in as `.jpg.png`, converted, and every surface flipped with **zero code changes**. 6 Aug 03:13: an 11-icon grid became mask-tinted icons in the dock, rail, credits pill and menus; 05:24 the "ring says assemble once" correction; the closet icon was declared "never change again". Per-look 3D models: 58 MB → 6 MB and 54 MB → 5.4 MB.

## Step 5 — Feature and polish rounds (data truth, monetisation, grammar)

Each round starts with your click-through notes and the question-round contract, and ends with build → verify → push → docs sync → delivery report. Things that every app needs and Assemble settled in rounds 4–8:

- **Data-driven screens over duplicated screens**: one data object per entity (`LOOKDB`, `PRODDB`, friends, swaps); every card carries its id; one detail screen per entity type. When you are tempted to ask for "custom screens for each option", ask for data-driven ones.
- **Choices vs actions grammar**: choices (chips, option rows) get a leading selection dot; forward buttons are gradient pills with a trailing arrow; secondary buttons are squarer. Applied app-wide as one system, because "the Next button looked the same as selecting weather".
- **Money as real state**: credits balance, per-action cost, gates that open the Buy sheet when short, usage rows prepended live; *AI pass = credits, manual edit = free*, with a paid "render the result" after a manual change.
- **Truthful demo data**: counts match visible items; everything a look marks "owned" exists in the closet; "I bought this" really adds the item.
- **Copy**: no backend-speak ("type at least 2 characters"); "Continue with Google", not "Gmail".
- **Modals** close on backdrop tap (a grab-handle hint, no ✕ on ~75 modals).
- **Consent** consolidated to one signup checkbox where legally defensible; per-generation attestation where each run uses new photos.
- **Portrait 3:4 everywhere** for people, capped at 400 px wide on desktop.
- **Signature loader**: the animated logo as the single "processing" signature, including the 3D build.
- **Numbered-path screens** when a screen offers several ways to start (gradient number chips, benefit-led lines, the call-to-action appears only after a choice).

> **For Claude — paste this (punch-list round):**
> ```
> Here's what I noticed clicking through [APP] on my phone: 1) [issue] 2) [issue] ... For each, propose the fix and look for the same problem elsewhere in the app. Ask at least [N] questions to understand, discuss and take decisions together — one by one, multiple choice, recommended option marked. Then build all, verify in the browser, sync the flow charts / Coverage / Walkthrough / Presenter Script, push main, and report with numbered sections matching the decisions, what you verified with numbers, the commit hash and my one to-do.
> ```

> **Assemble example.** Rounds of 47, 67 and 31 decisions on 5–6 Aug, each built in 15–20 minutes. Round 5 (22:32 → 00:05) made AI detection paid for everyone (your one-sentence correction: "this is not a subscriber perk"), added `LOOKDB`, live friend search and an interactive Get Started checklist. Round 6 added paid refine, real swap + "render updated look · 1 credit", inline rename, 52 SVG back chevrons, the animated dock, and the icon brief. Round 8 (after a context compaction at 07:26) redesigned the Match screen around three numbered paths (`f5cf4e6`). The last delivery question was dismissed once ("do not proceed, wait") and Claude waited.

## Links inside sentences (added from the next app)

A link surrounded by text is **always underlined**, never colour alone — WCAG
1.4.1, and axe fails it as `link-in-text-block`. A link that stands on its own
(a row, a card title, a "See all") may use colour plus hover underline. Put the
rule in the design standard; the accessibility sweep will find the ones you
forget.

## Pitfalls (UI)

| Symptom | Cause | Fix / prevention |
|---|---|---|
| Private repo "Not Found" on import | Token from another account, or a fine-grained token not granted this repo | `/user` + repo lookup with the API before cloning; get a token from the owning account |
| Bearer auth rejected by git over HTTPS | git expects basic auth | Basic auth with the token as password, one-off; or the inline URL for a single push |
| Vercel "deployment blocked" | Commit author not a collaborator (Hobby + private repo) | Repo-local identity = owner noreply; rewrite the branch commits with `--reset-author`; force-push with lease |
| `--force-with-lease` refused | Inline-URL pushes never updated `origin/<branch>` | Fetch or pass an explicit `branch:sha` lease |
| Old greyscale UI still showing locally | A stale local server from an earlier session on another port | Check who owns the port; use a project-specific port; restart |
| Orbit logo invisible | `calc()` division of a length inside `scale()` | Explicit unitless scale variable |
| Icons vanished on the dark theme | Placeholder icons assumed a light background | Grep for light-theme assumptions; light tiles behind product icons |
| WebP texture compression failed | sharp/libvips issue on the machine | Draco geometry-only (still ~90% smaller) |
| Browser pane cannot save rendered images | Cross-origin fetch and downloads blocked | Same-origin Node dev server with `POST /save` |
| Screenshots fail | Pane hidden | DOM measurements; screenshots only when the pane is displayed |
| Edit tool fails on the huge file | Invisible mismatches | Python line-splicing / count-asserted replacements |
| Inline Python in PowerShell breaks | Quote and here-string escaping | Always `.py` files in the scratchpad |
| Some generated PNGs will not decode | GDI+ limitation | Use Pillow |
| Wrong crop offsets | Assumed sheet width (2816 vs 2752 px) | Read the real dimensions first |
| Grid does not follow the prompt (5×3, duplicates, shuffled) | Generator behaviour | Baked labels; ≤ 9 cells per sheet; map by label; cherry-pick by position |
| Double extension files | Save dialog | Normalise on intake |
| New buttons do nothing / fall through to navigation | New `data-*` attribute missing from the delegated `closest()` list | Keep the list next to the vocabulary; add every new attribute |
| Detail title ignores the tapped item | Screen read a default instead of state | Every entity screen reads identity from state first |
| Toast disappears immediately | `go()` clears the toast | Call `go()` first, then set the toast, then `render()` |
| Selection dot overlaps text / opt-out ignored | CSS order and specificity | Append overrides after base rules; match specificity for opt-outs |
| "Move" moved the menu chip, not the card | The chip carried the same `data-*` id as its card | Scope queries to grid cells |
| Icon bottoms clipped | Label-trim crop zone too small | Check glyph bounding boxes against the crop window; re-slice |
| Ring text repeated like a pattern | Prompt did not say "once" | "EXACTLY ONCE per ring; the rest of the ellipse is a plain line" |
| Wrong numbers in demo data ("143 items", "All · 8" showing 4) | Hard-coded counts | Derive counts from data |
| Recommendation built on a wrong product assumption | Claude guessed a rule (detection as a subscriber perk; the four photos used for 2D) | State the monetisation and data rules at the start of a round; correct in one sentence; save to memory |
| Context ran out mid-project | ~28 hours of session | Memory updated after every round makes the auto-summary resume seamless |
